# Private review builds on GitHub

Main Windows CI stores fully tested builds as draft prereleases in this private source repository. This uses GitHub Release asset storage rather than the Actions artifact quota. Repository users with write access can open Releases and select the draft titled **Review genesis** or **Review hub**. Drafts are not public downloads or approved distribution candidates.

Every draft is bound to the full source SHA, Actions run ID and run attempt. It includes review-build.json with original file sizes/SHA256 values and the run link. Storage verifies the exact uploaded asset inventory and GitHub server-reported sizes/SHA256 before reporting success. Missing digest, missing files, wrong/private status, non-main or untrusted event identity fail closed. No old build is overwritten or deleted; an incomplete upload remains an unapproved draft for investigation. Rerun with a new Actions attempt to get a new identity.

Genesis includes the full Windows ZIP, three component ZIPs and candidate report. Hub includes the unsigned development installer, core/updater logs, checksums and available native screenshots. Builds must pass their real native/exported-game/bundled-model checks (Genesis) or installer/bootstrap/navigation/uninstall checks (Hub) before storing anything. Feature/PR tests retain read-only repository permissions; only the first-party main storage job has contents-write permission, and its GH_TOKEN is passed only to the upload step. Checkout does not persist credentials. No cross-repository token, signing key or billing change is needed.

These are private inspection copies visible to repository users with push/write access; they are not strictly owner-exclusive. Do not publish/promote the draft, mirror it to the public release repository, or put its link in website/Hub download controls. Production signing, original/third-party license acceptance, independently inspected package bytes, target-device tests, Android parity and protected production publication remain mandatory. Checksums prove byte identity, not trusted publisher identity. Source/build locks and public catalog gates remain unchanged.

To inspect: download the files from the authenticated draft page, compare SHA256/size against review-build.json, then inspect/unpack the archives in a separate test workspace. Use the documented backup and isolated-save procedure before running a development build. Record acceptance against this exact source/run/package, never an earlier artifact.
