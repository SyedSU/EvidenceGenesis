# Native save safety — 2026-10-13

Genesis0.5.0 remains a development candidate; save format/compatibility epoch4 is unchanged. This source fixes failed-save handling and recovery and adds mandatory native file persistence. It does not approve public distribution or reuse of older built artifacts. Actual source/validation evidence is recorded in canonical RELEASE-STATE.md.

Workshop saves and the profile index share GenesisSaveFiles. The writer validates bounded JSON and existing originals/backups, writes unique same-directory stages, flushes/checks write status, closes and verifies exact bytes, then syncs the stage through the bundled native adapter. It stages the previous backup before replacing it, checks replacement/recovery outcomes, and retains verified recovery stages when rollback fails. Failed first writes cannot activate a partial stage. Invalid or oversized data cannot replace previous files.

Care/task/profile/settings changes roll back on failure. Feed/harvest/rest cannot grant persisted progress; a full task queue restores evicted history. Failed profile creation leaves the previous index/selection intact and retains any unindexed new profile rather than deleting it. Settings and autosave report errors; ordinary Exit refuses a failed active save so the user can correct it and retry. Menu startup without a writable profile can still Exit.

Missing primary: read only a validated `.backup`, with a recovery message. Present corrupt primary: preserve original bytes, disable writes, and copy readable bounded bytes to `.corrupt-<SHA256>` when possible. Never silently replace corrupt primary data. Unreadable/oversized originals remain preserved even when quarantine is unavailable; invalid existing backups block replacement.

Recovery: stop gameplay writes and copy the whole EvidenceGenesis directory, normally `%APPDATA%/EvidenceGenesis`, before repair. Preserve primary, `.backup`, `.corrupt-*` and any recovery stage named by the error. Fix free-space/permissions/incorrect-directory problems and retry. If recovery itself fails, use the verified backup/stage identified by the error. Restart to the main menu and use Restore backup to create a separate restored workshop when no healthy current profile opens; retain the corrupt original. Corrupt index files are preserved for manual backup/support recovery, not automatically rewritten. Never remove legacy originals or blindly restore a different save epoch.

## Native persistence continuation

A first-party x64 C GDExtension now replaces the two insufficient Godot primitives. It uses the reviewed4.7.2 ABI header generated by the verified engine (MIT notice retained); no godot-cpp, command helper or player compiler/Python is required. On Linux it syncs regular staged files with fsync, performs same-directory rename and syncs the parent directory. On Windows it uses UTF8→UTF16 paths, FlushFileBuffers and same-directory MoveFileExW with REPLACE_EXISTING/WRITE_THROUGH, without delete-first or cross-volume copy fallback. Unsupported platforms/missing libraries fail closed. This source does not assert hardware/filesystem power-loss guarantees.

A native status distinguishes failure before replacement from uncertain sync after replacement. Uncertain status preserves active/backup/recovery stages and refuses further writes through that storage instance until reload; the error says disk state may have advanced. Reload validates the actual on-disk generation. Do not keep retrying a durability error; copy the complete save tree first. Symlink/reparse leaf files and directory/cross-directory replacements are refused by the native primitives; ancestor links, exclusive transaction locking and hostile directory races remain limits.

## 2026-10-23 transaction isolation continuation

Every workshop and profile-index read/write now holds a nonblocking native OS lease for the complete read/validate/stage/backup/replace/recovery transaction. Windows uses a non-sharing file handle; POSIX uses flock with a guarded per-process handle table. Process termination releases the lease. Persistent `.lock` files are coordination objects: leave them in place and never delete them to try to release a running process's lock. Busy readers/writers return an actionable error instead of racing recovery or backup rotation.

Each in-memory workshop/index records the observed primary and backup content hashes. Writes compare both while holding the lease; a stale instance must reload rather than replace newer work. A fresh object cannot overwrite an existing save without reading it. Switching to a new profile path resets the expected revision to absent, preserving explicit legacy import. Failed application changes still roll back. A verified non-uncertain failure which retains the original primary and safe backup refreshes only its own revision, so retry after a transient first-backup replacement failure remains possible. Stale-writer rejection never adopts another writer's revision. This tracking does not change JSON format or compatibility epoch4.

Local Godot4.7.2/Python validation:32 tests,31 passed and one Windows-only skip;96 existing save assertions and10 kill/reload cases retained.
